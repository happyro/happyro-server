# NPC 完整名称同步

HappyRO 固定使用 PACKETVER=20211103。标准实体出现、移动和名称响应中的名称字段只有 24 字节，C 字符串最多容纳 23 字节正文；中文名称可能在这里被截断。移动端标题使用实体名称，桌面对话正文来自脚本 `mes`，因此两处曾显示不同结果。

服务端向标准实体出现、移动、名称响应之后追加 `ZC_HAPPYRO_NPC_NAME`（0x0d04）：

| 字段 | 长度 | 含义 |
| --- | --- | --- |
| packetType | 2 | 0x0d04，小端 |
| packetLength | 2 | 整包字节数，小端 |
| npcId | 4 | 实体 ID，小端 |
| name | 可变 | UTF-8 名称和末尾 NUL，含内部 # 后缀 |

接收层已读取包号和长度，结构解析器从 npcId 开始。完整名称通过 `localizeEntityName` 写入实体名称，头顶、移动对话、商店等共用同一来源；不修改头衔、队伍、公会字段。不根据脚本中的 `[说话人]` 猜测实体名称，因此微笑助手/微笑女孩等不同说话人仍按原有规则显示。

服务端对固定长度文本字段采用 UTF-8 字符边界截断，内部 NPC 展示名称的 50 字节上限也遵循此规则。固定字段的容量不变，超长 NPC 展示名称通过扩展包完整传输（以内部 50 字节上限为准）。客户端与服务端需要同时更新；不改变标准封包尺寸，不新增旧版兼容分支。
