# 自动注册错误码

HappyRO 固定 PACKETVER=20211103，沿用 AC_REFUSE_LOGIN（0x083e）及原有字段布局，错误字段为 uint32。不改普通登录的错误码 0（账号不存在）和 1（密码错误）。

服务端定义位于 `src/login/registration.hpp`，客户端映射位于 `src/Engine/Auth/RegistrationValidation.js`，两端修改时同步核对。

| 错误码 | 原因 |
| --- | --- |
| 200 | 注册账号短于服务端配置的最小字节数 |
| 201 | 注册密码短于服务端配置的最小字节数 |
| 202 | 注册账号已存在 |
| 203 | 自动注册限流 |
| 204 | 数据库创建账号失败 |
| 205 | 未开放自动注册 |
| 206 | 当前密码加密方式不支持自动注册 |
| 207 | 注册性别无效 |

识别 `_M`/`_F`（大小写均可）后，即使注册关闭或密码为空，也按注册请求返回明确原因。普通登录仍执行原来的认证规则。客户端提前校验当前 HappyRO 规则；服务端使用自己的配置作最终判定。登录日志记录各注册失败原因，这些失败不进入仅针对错误码 0/1 的密码失败封禁统计。

账号与密码按 UTF-8 字节计数。当前自动注册账号本体为 6～21 字节，预留两字节性别后缀；密码为 6～23 字节。客户端在序列化前拒绝超长输入，避免固定长度封包截断；服务端无法恢复发送前已被客户端截掉的内容。

部署需同时更新 Gateway（客户端）与 Server（login-server）；不涉及数据库迁移。客户端对未知登录错误显示原始错误码，不将未识别错误静默映射为密码错误。
