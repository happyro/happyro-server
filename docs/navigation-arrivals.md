# 冒险工具默认传送落点

## 选择规则

`HAPPYRO_MAP_TELEPORT` 和游戏控制接口的坐标 `(0,0)` 表示请求自动选择落点，不再表示随机落点。封包结构和 PACKETVER=20211103 不变。`(65535,65535)` 请求随机安全落点，其它非零坐标按明确目标处理。

1. 已配置的十四城使用固定默认坐标，并在附近十二格内进行安全校验与调整。
2. 其余名单地图按顺序查找当前已加载的服务 NPC，检查地图、可见性及角色可用性，在其当前位置周围二至六格内寻找安全格。一个候选不可用时继续下一个。
3. 已审核的普通地图入口使用 `happyro_entrance_arrivals` 中的入口安全锚点；附近十二格调整需与锚点步行连通，锚点不可通行或无同区域安全格则拒绝。
4. 其余没有合适服务 NPC 或入口规则的地图，从地图中心向外逐圈寻找安全格，最多搜索覆盖整张地图的范围；仍无可用位置则拒绝传送，不随机回退。

所有分支保留传送权限、跨地图开关、冷却、禁止传入/传出地图和职业进入限制。自动落点不授予额外权限，不修改任务脚本。显式坐标仅在附近十二格内调整，不转去服务 NPC。脚本原有传送阵与普通跨图寻路不变。

安全格要求可通行、未被角色或 NPC 占用，且避开完整 OnTouch 区域和其两格边距。实际可用性以运行中的服务端为准。

## 修改与回归边界

- 公共入口必须有已审核来源、固定双向路径和入口到落点的步行连通性；不要把收费、任务或随机传送当作无条件入口。
- 室内、多房间与隔离区域分别核对；不因主区域面积大就自动批准，不跨墙或跨房间调整坐标。
- 服务 NPC 必须与公共入口连通，检查完整触发区及两格边距；距离仍为二至六格，不为了满足候选点扩大范围。旅馆落点不自动执行住宿、收费或任务。
- 昆仑迷宫、条件入口和未确认房间继续待审；拉撒格纳服务点触发区与安全距离冲突，不能直接套用当前服务点规则。
- 核对地图缓存、脚本加载关系、NPC 隐藏／停用／移动引用、动态占用与来源清单，并运行实际选点函数的回归测试。
- 无安全点时拒绝；随机模式不回退默认入口。`0x0d00` 长度保持 26 字节，权限、冷却和地图进入限制不变。

部署配套客户端与 map-server，重启后核对实际版本。批量地形校验、编译与回归通过不代表逐图真人传送、旅馆服务或任务事件链均已验收。阶段构建和服务状态查 changelog／Git，不作为当前在线状态保证。

## 只读落点预览

`0x0d06` 请求共 22 字节（int16 封包号、uint32 requestId、char[16] 地图名）；`0x0d07` 回复共 28 字节（int16 封包号、uint32 requestId、uint16 result、char[16] 地图名、uint16 x/y），均为小端序，结果码沿用地图传送枚举。PACKETVER 不变，需配套部署客户端。

预览复用正式传送的权限、频道归一化、地图限制及安全选点，成功时只返回坐标；不调用 pc_setpos、不改变传送冷却或写传送日志。单角色请求至少间隔 500ms；客户端 200ms 防抖并以至少 600ms 间隔请求，不轮询。无预设地图的中心搜索限半径 24 格，无法预览不等于正式传送失败；正式传送仍完整搜索并重新检查动态占用。客户端紫色标记注明预计位置，默认传送继续使用 `(0,0)`。
